# 简介

自用的Windows文件备份软件。
- 支持 本地目录/SMB 备份到 本地目录/SMB/WebDAV/SFTP。
- 多版本：不同时间节点的文件共存，方便找回历史文件。
- 多任务：可以自由勾选待备份的文件/文件夹。
- 通用性： **备份文件是普通的7z压缩包，可以用常用的解压软件解压**，加密方式为 7z aes-256，压缩方式为LZMA2/Copy(自动控制)。
- 容灾：仓库可随意组合raid0/raid1(可嵌套但不可循环引用)；备份文件相互独立， **即使丢失大部分备份文件，剩余部分仍可用于恢复**。
- 传输优化：在以openlist的webdav为自动备份目的地时，网络不稳定很容易造成备份失败，若备份目的地的部分文件丢失则可能会导致整个任务被锁定，无法继续备份或恢复，本软件专门对此做了优化，对文件被删除或上传缓慢等情况可以有效处理(不是加速，只解决上传超时/目的地损坏等情况)。
- 性能优化： **软件本身不扫描硬盘，不建立索引**，直接读取Everything索引并缓存 用于监控文件变化。
- 软件为绿色纯净版，双击打开即用.无需安装，定时任务使用windows自带的任务计划程序，软件本身不安装Windows后台服务，软件运行数据都在安装目录内，删除文件夹=卸载(需先删除或暂停定时任务)。

#### 从源码构建
1.在这里下载[Backup-fang523-code.zip](https://github.com/josemims31/backup/archive/refs/heads/main.zip)  
2.解压  
3.在源码根目录 `shift+右键` 选择 `在此处打开powershell`  
4.输入以下命令并回车进行构建：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-ui.ps1
```

脚本使用系统自带的 64 位 .NET Framework C# 编译器，同时编译主程序、Core 和四种内置仓库模块。正常构建不需要 Visual Studio、.NET SDK 或 NuGet 联网还原，所需第三方依赖随完整源码提供。

构建输出位于 `build/`，这个文件夹就是完整的软件安装目录，注意： **每次构建都会删除并重新生成整个 `build/`**，因此应将它剪切/改名到其他位置使用，安装目录下的Backup.exe就是主程序。


### 压缩、分卷、内存和传输

备份文件是普通的7z压缩包，可以用常用的解压软件解压，加密方式为 **7z aes-256**，压缩方式为LZMA2/Copy(自动控制)。

内存操作预算默认 **2048 MiB**，允许设置为 256～65536 MiB。内存预算影响备份文件的分卷大小，自动分卷大小如下：

| 内存配置 | 分卷大小上限 |
| --- | --- |
| 768 MiB 及以上 | 200 MiB |
| 512～767 MiB | 100 MiB |
| 256～511 MiB | 50 MiB |

小归档和最后一个分卷可以小于上限。内存预算用于协调缓冲、读取和压缩相关操作，不是在启动时把整个预算全部分配，也不是 Windows 对整个进程内存的硬性上限。界面、数据库、协议库等还会占用额外内存。

程序边读取、边打包、边上传已经形成的分卷。当前统一传输调度为：
- 上传最多同时 5 路，同一仓库最多 3 路；正常备份和完整性修复共用调度。
- 下载最多同时 16 路，所有仓库、文件和单文件分段共用此上限。服务器支持时，同一文件也可以分段下载，空闲线程可协助补齐较慢的剩余分段；不支持时按可用方式读取。
- 设置支持按时段限制上传、下载速度或暂停传输。

### 仓库和目录结构

单独的仓库可以作为目标，也可以组成组合，RAID0：按已用容量(百分比)自动分配，RAID1：每个仓库存一份。允许嵌套但不能循环引用。它们是软件的备份分配规则，不是磁盘阵列驱动。

每个任务有稳定的四字符代号，用于新增备份文件命名和任务目录隔离。新建任务会检查代号冲突；修复和整理沿用所属任务的代号。

例如将仓库根目录设置为 `backup`，新文件采用以下结构：

```text
backup/
├─ catalog-时间戳.7z
├─ data-aAan/
│  ├─ 000001/
│  │  ├─ data-aAan-时间戳.7z
│  │  └─ data-aAan-时间戳.7z.001 …
│  └─ 000002/
├─ node-aAan/
│  └─ 000001/
│     └─ node-aAan-时间戳.7z
├─ data-R7qt/
└─ node-R7qt/
```

`data-代号` 保存数据，`node-代号` 历史版本数据库，`catalog` 主数据库快照包 放在仓库根目录。子目录按每900个对象一个分配槽继续增长，按需创建；新目录不会通过搬动旧文件来腾位置。目录分配不是根据每次联网扫描重新计算的。

数据库记录的路径用于定位文件。完整性检查依靠文件名称和大小判断，实际需要读取已登记的分卷用于恢复或修复时 再校验哈希。 
**不要把已通过完整性检查理解为已经验证所有备份文件的内容。**

数据包即使被手动移动了位置，只要还在任务目录下，就可以自动识别 用于恢复数据。

### WebDAV 与 OpenList 上传优化

添加或编辑 WebDAV 仓库时，“openlist上传优化(首次登录需要输入2fa)”默认勾选：

- 勾选后：自动识别 OpenList；普通WebDAV使用普通上传流程。
- 取消勾选：直接使用普通WebDAV上传流程。
- 识别并授权后，可提交原生上传任务、查询服务端进度及任务状态。
- 未启用 2FA 时验证码可留空。同一 OpenList 服务、同一账号的不同仓库共享授权，令牌加密保存并可跨重启复用，不要求每次备份重新输入。
- 运行中授权失效或需要 2FA 时弹出授权窗口；连续 5 分钟无输入，会自动改用普通WebDAV继续处理新的上传，并标记仓库为“无openlist优化”状态。
上传结果不确定时会保留原目标并记录原因。一般按每 20 秒一次、最多三次核对，再进入最多三次重传。
- “上传结果待确认”不表示文件必然丢失。正式文件的名称、大小以及服务端任务状态还需要核对；日志会记录进入核对的原因和核对结果。

### 备份版本和保存时间

每个成功完成的任务备份保存一份独立文件清单，记录当时的文件及其归档引用。

保存时间绑定任务，新任务默认 **1 年**，可输入正整数并选择天、月或年。智能轮换保留：

| 版本年龄 | 保留方式 |
| --- | --- |
| 过去 24 小时 | 每小时最早创建的版本 |
| 24 小时至过去 1 个月 | 每天最早创建的版本 |
| 更早 | 每周最早创建的版本，周一开始 |

额外保留最新成功版本。

成功备份后执行智能轮换；保存时间的硬性期限在修复完整性时执行，超期版本全部移除(最新的一个版本例外)。移除版本后，仍被其他版本使用的数据包保留，无引用的数据空间在修复完整性时回收。

### 完整性检查与修复

“检查备份完整性”和“修复备份完整性”是独立的全局操作，不受当前浏览筛选限制，会直接对全部任务进行检查/修复。

| 操作 | 依据和行为 | 数据库快照同步 |
| --- | --- | --- |
| 开始备份 | 先取得Everything索引，按任务范围读取、打包和上传 | 成功保存版本及轮换后同步数据库，无变化时跳过 |
| 检查备份完整性 | 根据仓库目录元数据和待备份清单修正本地登记状态 | 不上传数据库快照 |
| 修复备份完整性 | 根据本地登记、已有检查结果和可用来源操作仓库 | 实际发生相关变更后同步数据库 |
| 整理压缩包 | 读取已有备份，将小压缩包合并为大压缩包 | 完成合并后同步数据库然后清理旧包 |

### 暂停、停止和退出

- 暂停：暂停本机读取和传输，保留缓存，可随时继续。
- 停止：立即停止读取，但继续上传已经打包完整的压缩包。
- 立即停止：取消读取和传输，释放缓存并尝试清理未上传完成的压缩包。
- 修复完整性时停止：取消当前修复的读取和传输，保留有效副本及需要重试的状态，不采用正常备份继续上传缓冲的停止方式。
- 关闭软件：取消当前工作，等待连接、后台读取和数据库释放后退出。

大文件的某几个分卷上传成功，不代表这个大文件已经可恢复。未完成或没有有效成功结果的压缩包不会被数据库引用，远程残留可由后续检查识别，并在修复时清理。

### 任务计划

支持每日、每周、每月计划，可关联多个任务。计划中的“检查完整性”会依次执行检查+修复(仅所选任务)。

计划通过 Windows 任务计划程序运行，使用对应 Windows 用户的已登录会话。程序未打开时可以由系统启动；错过计划按系统任务配置补跑。同一安装目录的请求通过进程通信和持久队列交给运行中的程序，避免重复启动同一份任务工作。移动安装目录后，应核对计划页面的系统任务状态。

导入的计划默认停用，需要核对关联任务及路径后手动确认、启用。

### 原仓库地址失效，备份包已下载到其他位置

保留当前数据库时，可将原仓库配置切换到实际可访问的位置，备份包文件不全也可以切换。选择不自动迁移，然后检查完整性(不要修复)，再从任务视图恢复。读取时会结合文件名、大小和实际内容校验，部分压缩包丢失也不妨碍其他完整压缩包中的文件恢复。

如果需要导入主数据库，先用数据库备份密码解密 `catalog-*.7z`，得到其中的 `catalog.db`，再在“备份任务”中点击“导入数据库”。导入选择的是解密后的数据库文件 **catalog.db**，不是原始加密包。

### 只剩压缩包，没有任务或数据库

知道数据包密码时，可以使用7-Zip或其他解压软件手动解压并提取可用的内容，应按照文件名顺序(文件按时间命名)从小到大顺序解压，避免出现新文件被旧版覆盖，可能会出现一些本来已经被删除的文件(压缩包内部分文件被数据库标记为已删除但还有一部分文件有用，完整性修复时不会删除整个压缩包)。  
另外，整理、修复重新打包后，旧版本内容也可能出现在新命名的包中。没有版本数据库时，可以提取内容，但不能仅凭包名保证恢复出最新状态。

### 覆盖与合并(数据库导入)

覆盖：校验导入数据、保存当前数据库的回滚副本，再替换主数据库。
合并：只导入选定的 任务、仓库、定时任务，保留本机的全局设置，按配置内容判断重复，可多次导入。

| 项目 | 重复判断 |
| --- | --- |
| 待备份目录 | 规范化后的实际目录地址相同 |
| 仓库 | 传输协议和实际地址相同 |
| 任务 | 有效勾选范围和目标仓库相同 |
| 定时任务 | 映射后的关联任务、执行操作、周期、时间相同 |

合并只带入所选项目及其所需数据，不会为了满足依赖而自动导入未勾选的仓库或任务，新导入的任务计划默认停用(需要手动启用)。

更换 Windows 用户或电脑后，原用户加密保存的仓库连接密码、私钥口令和OpenList授权令牌通常不能直接解密，需要重新配置。数据包及数据库密码也应另行保管。

### 本地数据和缓存

运行路径以 `Backup.exe` 所在目录为准：

| 路径 | 用途 |
| --- | --- |
| `data/catalog.db` | 任务、仓库、设置、版本登记、归档位置、恢复信息，以及本地未完成清单 |
| `data/node-任务代号/版本标识.db` | 已保存版本的本地文件数据库，例如 `data/node-aAan/…db` |
| `cache/working-files.db` | 当前任务的增量比较工作清单 |
| `cache/metadata.db` | 来源索引和仓库目录等运行缓存 |
| `cache/schedule.db` | 计划请求队列和界面状态 |
| `cache/logs/` | 上传、运行和错误日志 |
| `cache/catalog-before-*.db` 等 | 导入等操作生成的本地回滚副本 |
| `cache/` 下其他运行文件 | 构建或运行临时数据、操作缓存和必要的重试资料 |

`cache/` 不等于可以随时删除的纯临时目录。升级时建议保留整个 `data/` 和 `cache/`；运行中不要手动清理它们。仅备份 EXE 不能保留任务和恢复信息。

主数据库和解密后的数据库快照包含恢复信息及压缩包密码，应按敏感文件保管。仓库连接凭据和 OpenList 令牌使用Windows用户级DPAPI加密。

### 仓库模块开发

内置模块源码分别位于 `src/Backup.Repositories.Local`、`Smb`、`WebDav`、`Sftp`，构建后按类型分目录：

```text
repositories/
├─ local/Backup.Repository.Local.dll
├─ smb/Backup.Repository.Smb.dll
├─ webdav/Backup.Repository.WebDav.dll
└─ sftp/Backup.Repository.Sftp.dll 及其依赖
```

主程序与 Core 统一管理会话复用、目录刷新、请求合并和传输队列。当前目录刷新请求会合并；成功结果设有最短刷新间隔，失败结果也会短暂缓存，避免多个功能重复遍历同一目标。这些间隔不是自动定时扫描所有仓库的周期。

扩展模块使用仓库接口版本 1，引用当前 `Backup.Core.dll`，实现公开模块入口。将编译好的模块及其私有依赖放入 `repositories/自定义子目录/` 后重启，即可发现新类型，不需要重新编译主程序。只扫描第一层模块子目录，不递归发现更深层的模块入口。

接口、示例、目录规则和测试要点见 [仓库模块开发文档](docs/仓库模块开发.md)。模块是会在本机进程中执行的代码，应安装可信来源的模块。第三方组件的许可说明随对应构建文件提供。
